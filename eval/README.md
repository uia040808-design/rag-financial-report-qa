# 引用评测（eval/）

量化 `_validate_page_references` 的过滤能力与最终产出质量。这个目录存在的
理由：项目原本**没有任何页码标注、没有任何评分脚本**，所以"引用校验能拦住
幻觉"这句话此前无法被验证，只能靠读代码相信。

## 快速开始

```bash
python -m eval.build_annotations            # 生成标注集
python -m eval.score_citations --detail     # 看逐条明细
python -m eval.score_citations --save-baseline
python -m eval.score_citations              # 与基线对比，劣化则退出码非 0
```

前置条件：`data/stock_data` 下已有分块报告与 markdown（先跑
`python -m src.pipeline` 的 `chunk_reports` 阶段）。

## 标注集怎么保证可信

`annotations.json` 里的**页码不是手写的**。每条标注由 `seeds.py` 里的
`(问题, 页码锚串, 标签, 类型)` 生成，`build_annotations.py` 在
`content.pages` 原文里检索锚串得到页码，并对锚串做**全局区分度筛查**。

### 区分度筛查（`screen_seeds`）

只按单文档计数是不够的，踩过一次具体的坑：种子 `'22.5%'`（1Q25 毛利率）在
每份文档里各命中 ≤4 页，**逐文档检查全部通过**，可它其实是无效标注 ——
`normalize()` 会剔除小数点与百分号，`'22.5%'` 归一化成 `'225'`，在全语料里
命中 **31 页**，绝大多数是 `1,225`、`225.0` 这类无关数字。`'22.6%'` → `'226'`
命中 35 页。同样的问题让 `page_index_roundtrip` 从 100% 掉到 95.2%，看起来像
页码映射出错，实际是指纹本身指错了地方。

因此筛查是**一次性全局**的（不是逐文档重复判定）：

| 检查 | 阈值 | 拦什么 |
|---|---|---|
| 归一化后长度 | ≥3 字 | 过短，任何巧合匹配都可能命中 |
| 纯数字锚串长度 | ≥8 位 | 小数点被剔除后的退化数字串 |
| **全语料命中页数** | ≤6 页 | 跨文档无区分度（逐文档检查看不出这一类） |

两侧都必须是**归一化后**的文本。拿归一化锚串去搜原始 markdown（含 `#`、
`<table>`）会永远命中 0 次，上限检查形同虚设 —— 这是本检查最初实现里的实际 bug。

通过的纯数字锚串仍会列入 `[需人工确认]` 清单，因为归一化剔除小数点后它可能
指向另一个数字。当前 5 条：`'561680787'`(命中 2 页)、`'57795570'`(4 页) 等。

### 规模

**46 条标注，覆盖全部 9 份文档，真值页合计 63 页**（单页真值 33 / 多页真值 13）。

| 文档 | 标注数 |
|---|---|
| 年报（222 页） | 21 |
| 调研纪要 | 5 |
| 华泰 / 中原 / 光大 / 国信 / 东方 / 上海 / 兴证 | 12 |

原先 21 条种子全部指向年报措辞（"年报中…"、"资本开支与上一年持平"），导致标注集
21/21 落在同一份 PDF 上，**跨文档行为完全无法度量**，且记录的 `pdf_sha1` 还是旧
语料的占位符 `stock_10001`。现按"该事实出自哪类文档"分组补齐：券商研报的
评级/目标价/盈利预测、年报独有的口径、调研纪要的接待信息。

## 为什么指标分成两族

`min_pages=2` 的兜底补齐会往引用列表里塞检索 Top 页。如果和过滤逻辑放在同一次
调用里量，会得到无法解读的数：单页真值的标注必然触发补齐，于是"精确率"被
兜底稀释、"补齐相关率"恒为 0（补进去的页按构造就不是已声称的页）。

所以 `score_citations.py` 分两族量：

| 族 | 配置 | 回答什么问题 |
|---|---|---|
| **A 过滤能力** | `min_pages=0`（关闭兜底） | 该留的留住了吗？不该留的拦住了吗？ |
| **B 端到端** | `min_pages=0 / max_pages=8`（生产实际） | 最终提交物里有多少是真引用？ |

> `PROD_MIN_PAGES` 必须与 `questions_processing.get_answer_for_company` 的实际
> 行为保持同步（该调用不传 `min_pages`，走默认值）。改动生产侧默认值时，
> 忘记同步这里会让评分结果毫无变化 —— 这个坑踩过一次。

离线模式调不到 LLM，拿不到模型真实的 `relevant_pages`。但校验函数的**行为**
完全由 `(claimed_pages, retrieval_results)` 两个输入决定，因此用受控输入穷举
其判定边界：

| 场景 | 声称内容 | 度量目标 |
|---|---|---|
| `oracle` | 全部真页 | 真引用是否被保留（误杀） |
| `hallucinated` | 越界 / 不存在的页 | 幻觉是否被剔除 |
| `full_context 面` | 同上，但检索面扩到全部页 | 范围检查是否独立于检索面 |
| `type_mismatch` | 真页码的字符串形式 | 页码类型能否归一化 |
| `in_context` | 检索到但非真值的页 | 上下文内错引是否被拦（机制边界） |
| `empty` | 什么都不声称 | 兜底塞了什么 |
| `quote` | 真值页的原文片段 | 引文能否解析出页码 |
| `fake_quote` | 不存在的引文 | 是否被正确拒绝 |

测量单项检查时会用**全页检索面**隔离，避免"未召回"被上下文检查抢先拦掉、
被误记成该项失败。

## 指标含义

```
[A] 过滤能力（min_pages=0，隔离兜底）
  filter_true_keep_rate            ↑好  真页码被当成幻觉剔除的比例的反面
  filter_hallucination_reject      ↑好  越界/不存在的页被剔除的比例
  filter_oor_reject_full_context   ↑好  ★ 检索面=全部页时仍能拦越界
                                         验证范围检查不依赖检索面（full_context 下不失效）
  filter_type_normalized           ↑好  字符串页码被转成 int 的比例
  filter_in_context_kept           边界  机制边界，非缺陷分：只判"是否给模型看过"，不判相关性

[B] 端到端（min_pages=0 / max_pages=8，生产实际配置）
  retrieval_recall                 ↑好  oracle 上界：只搜标注所属那一份 PDF
  naive_routing_recall_mean        ↑好  ★ 对照组：原实现的固定路由（9 种路由的均值）
  multidoc_retrieval_recall        ↑好  ★ 多文档合并排序；与上一行之差即改动净收益
  multidoc_docs_per_query          —   每次查询覆盖几份文档（原实现恒为 1.00）
  final_precision                  ↑好  最终引用中属于真值的比例
  final_recall                     ↑好  真值页被最终引用的比例
  padding_precision                ↑好  兜底塞入的页中属于真值的比例
  padding_pages_per_annotation      —   每条标注平均被塞进几页（纯浪费指标）
  page_index_roundtrip             ↑好  1-based->0-based 换算后能在原文命中锚串

[C] 引文路径（页码由字符串匹配得出）
  quote_resolution_rate            ↑好  真实引文能解析出页码的比例
  quote_page_precision             ↑好  解析出的页属于真值的比例
  fake_quote_rejected              ↑好  ★ 不存在的引文必须解析失败
                                         （若解析成功会直接造假引用，比失败危险得多）

[D] 多文档引用身份（引用 = sha1 + 页码）
  multidoc_samepage_distinct       ↑好  ★ 同号页码产出不同引用，不被去重合并
  multidoc_sha1_scoping            ↑好  ★ 引用按 sha1 限定范围
  multidoc_perdoc_range            ↑好  ★ 逐文档页码范围检查
  multidoc_ambiguous_dropped       ↑好  ★ 歧义裸页码被丢弃而不猜
  multidoc_single_doc_bare_page    ↑好  单文档时裸页码仍可用

[E] 引文改写的影响（每种改写分 正确/错误/失败 三档）
  quote_*_right                    ↑好  改写后仍解析到真值页
  quote_*_wrong                    诊断  改写后解析到**别的**页（评测构造造成，见下）
  quote_*_fail                     诊断  改写后解析不出任何页
```

E 族的 `*_wrong` / `*_fail` 属于 `DIAGNOSTIC_ONLY`：**只报告、不参与劣化判定**。
原因见"E 族"一节 —— 它们主要由评测的引文构造方式造成，会无谓抖动。

`filter_in_context_kept` 刻意不做成"缺陷分"。检索到的页即使不是本条标注的
真值，也往往是主题相关的；这个指标记录的是**机制边界**（校验不做相关性判断），
不是质量缺陷。

## [E] 引文改写的影响

真实观测（`answers_max.json`）：模型给的 `relevant_quotes` 有一部分**能在语料里
逐字找回**，却因为改写而解析失败被丢弃。常见三种改写：尾部截断、中间插省略号、
**顺序颠倒**（原文先"12.45 亿涨到 121.33 亿"再"波动性下滑"，模型反过来了）。

实测（63 个真值页引文，每种改写各测一次）：

| 场景 | 解析到正确页 | 解析到错误页 | 解析失败 |
|---|---|---|---|
| 尾部截断 | 88.9% | 4.8% | 6.3% |
| 中间插省略号 | 92.3% | 5.1% | 2.6% |
| 顺序颠倒 | 94.9% | 2.6% | 2.6% |

三点结论：

1. **「正确」档高不等于机制健全**。顺序颠倒的引文是靠*前缀缩短*缩回连续片段
   才匹配上的 —— 整条引文其实只用了前半段。指向对、覆盖不足，是另一回事。
2. **「错误」档（≈5%）主要由评测构造方式造成，不是生产风险**。引文由
   `_read_quote` 从页面机械截取，落在表格页时会得到 `'td营业收入td'` 这种标签
   骨架，归一化后仅剩通用词；真实模型引用的是完整句子。因此该档列为
   **诊断项，不进回归门禁**（`DIAGNOSTIC_ONLY`）—— 它会随标注集与截取位置变化
   而抖动，做门禁只会制造噪声。
3. 它揭示的真实风险是：**低区分度引文一旦凑够 `MIN_QUOTE_CHARS=8`，就会命中多页
   并被 `MAX_PAGES_PER_QUOTE=3` 截断，真值页可能被挤出**。这是阈值取舍，
   不是 bug —— 提高阈值会让真实引文更难解析。

> **不要**用"整条引文的前 N 字"去检索判断引文真伪。`normalize()` 会删掉省略号
> 和标点，模型在引文里插的 `……` 会让探针横跨原文不连续的两段，必然匹配不上，
> 从而把"改写"误判成"编造"。

## 引文路径的强不变量

引文式引用解掉"页码差一"的方式不是**拦截**，而是让该错误**在表示层面无法发生**。
可验证的不变量：

| 不变量 | 含义 | 实测 |
|---|---|---|
| I1 | 被采纳的引用，其页码与引文实际所在页一致 | **27/27 = 100%** |
| I2 | 解析失败的引文一律丢弃，不产生假引用 | 伪造引文 **21/21 全部拒绝** |
| I3 | 模型不再输出页码 → "页码与引文不符"这类错误消失 | 表示层保证 |

### 归因实验：解析失败是解析器弱，还是检索没召回？

`quote_resolution_rate` 是 93.1%，看起来像解析器有 7% 缺陷。**实际不是。**

把检索面从 top-10 换成全部页后，29 个引文 **全部可解析**，失败归零 —— 证明解析器
零缺陷，之前 2 例失败**全部由检索召回不足造成**（真值页 120、117 未进 top-10）。
不做这个归因实验，就会把检索问题误当成解析 bug 去修，改错地方。

### 已知取舍

- **只做精确子串匹配，不做模糊匹配**。模糊匹配会把引文解析到**错误的页**，
  那比解析失败更糟：失败会被丢弃并记日志，错误会带着合法 `pdf_sha1` 和合法
  `page_index` 进入提交物。放宽仅限两种确定安全的操作：省略号切分、前缀缩短。
- **引文真实跨页时只能解析到其中一个页**。这是内容本身的歧义（营业收入同时
  出现在 p8/p24/p120/p181），不是缺陷，但该场景下引用会少列一页。
- **单条引文最多采纳 3 个页**，按检索排名取。防止"本公司"这类高频短语产生
  几十条无意义引用；触发时会打 warning。
- 表格类事实（原文含 HTML `<td>`）可正常解析 —— 引文与页面用**同一套归一化**，
  两侧标签被一致地剥除。但模型若凭空添加原文没有的标签，引文会解析失败并被
  丢弃，这是正确行为（文本被改动，不应被信任）。

## 局限

- **检索排序由替身产生**。`retrievers.py` 用字符 n-gram TF-IDF 模拟
  text-embedding，零 API 依赖、确定性可复现，但排序结果与真实 embedding
  会有差异。因此 `*_retrieval_recall` 只能作参考，**引用机制类指标
  （`filter_*`、`padding_*`、`page_index_roundtrip`、`multidoc_*`）才可信**。
- **46 条标注 / 63 个真值页**。样本量适合做回归门禁，不适合宣称"引用正确率 XX%"。
  真值页分布高度不均（年报 29 页 vs 兴证国际 1 页），因此 `retrieval_recall`
  基本由年报的表现决定。
- `padding_precision` 只在 `empty` 场景下有意义；`partial` 场景里真值页已被
  声称，补进去的页按构造不可能是真值。
- **`naive_routing_recall_mean` 是 9 种路由的均值**，不是某一次实际运行的值。
  原实现的真实表现是一个区间（1.6%~39.7%），取决于文件系统返回顺序。

## 多文档检索：测出来的三件事

改造前 `retrieve_by_company_name` 命中首个 `company_name` 就 `break`。本项目
9 份文档的 `company_name` 全是"中芯国际"，于是所有查询都打到同一份 PDF。
同一预算（`top_n=10`）下的召回：

| 策略 | 召回 | 说明 |
|---|---|---|
| 原实现（固定路由） | **9.7%**（区间 1.6%~39.7%） | 完全取决于目录遍历顺序 |
| 多文档（纯全局合并） | **73.0%** | 每次查询覆盖 4.63 份文档 |
| 单文档 oracle | 92.1% | 已知答案属于哪份 PDF，**原实现不具备该能力** |

### 一、对照组必须选对

拿"多文档 73.0%"去比"单文档 oracle 92.1%"会得出**"多文档反而更差"**的结论。
这个结论是错的：oracle 假设已经知道答案在哪份 PDF 里，而原实现恰恰不具备这个
能力 —— 它连"是哪份"都不知道。对照组只能是**原实现本身**。

多文档距 oracle 还差 19.0 个百分点，这部分损失要用更大的候选预算换回来：

| `top_n` | 10 | 20 | 28 | 40 | 60 | 80 | 100 |
|---|---|---|---|---|---|---|---|
| 召回 | 73.0% | 77.8% | 84.1% | 85.7% | 90.5% | 93.7% | 98.4% |

`top_n=80` 才追平 oracle 的 92.1%。原因很直白：oracle 的 10 页全部来自正确
文档，多文档要先花名额证明"该看哪份文档"，等效预算就是 10 × 9 = 90。

生产配置正好落在这个区间：`llm_reranking_sample_size=30` 取候选 → LLM 重排 →
`top_n=10`。28 个候选时召回 84.1%，剩余由重排承担。

### 二、逐文档配额是错的（已实测否决）

我原本假设多文档召回低是"预算被摊薄"，于是实现了一个逐文档保底配额
（每份文档各取 `ceil(top_n/文档数)` 个候选再全局排序）。**结果更差**：

| 策略 | `top_n=10` | `top_n=28` | `top_n=80` |
|---|---|---|---|
| 纯全局 | 73.0% | 84.1% | 93.7% |
| 逐文档配额 | **55.6%** | **76.2%** | **88.9%** |

强制每份文档出场，会把名额花在无关文档上 —— 覆盖文档数从 4.63 涨到 6.30，
召回反而掉了 17 个点。**保留 `quota` 开关（默认关闭）只为让这个反直觉的结论
可被复现**，而不是留一个没人验证过的选项。

### 三、跨文档引用必须带文档身份

多文档下页码不唯一：年报和调研纪要都有"第 5 页"。9 份文档的真值页分布证实
重号普遍存在。因此引用一律是 `(sha1, 页码)`（`citation_resolver.Citation`），
不是裸页码。D 族 5 项指标全部 100%：

| 指标 | 含义 |
|---|---|
| `multidoc_samepage_distinct` | 两文档都有"第 5 页"时产出 **2 条**引用，不被去重合并成 1 条 |
| `multidoc_sha1_scoping` | 引用按 sha1 限定范围，不被另一份文档的同号页污染 |
| `multidoc_perdoc_range` | 第 12 页对 8 页文档越界、对 20 页文档合法，分别判定 |
| `multidoc_ambiguous_dropped` | 裸页码在多文档下无法确定来源时**丢弃**，不猜 |
| `multidoc_single_doc_bare_page` | 单文档时裸页码仍可用（多文档改造没把旧能力改没） |

"歧义就丢弃"是刻意选择：猜错会产出一条**带着合法 sha1 与合法页码、却指向另一份
PDF** 的假引用，比缺引用更难被发现 —— 后者至少是空列表，一眼能看出没引到东西。

原实现还有一处相关缺陷：`_extract_references` 用
`matching_rows.iloc[0]['sha1']` 从 `subset.csv` 取 sha1。subset 里同一家公司有
9 行，于是**所有**引用都被标成同一份 PDF 的 sha1，即使内容来自研报。现在
`sha1` 直接取自 Citation，不再查表。

## `page_index_roundtrip` 为什么是 98.2% 而不是 100%

这一项的参考系是 **PDF 文本层**（pypdfium2），而它**不是完整抽取**：扫描页需要
OCR，文本层会返回近乎空白。机构调研纪要 PDF 有 **6/22 页**属此类（<60 字）。

实测确认这不是页码映射错误：md 第 2 页与 PDF 第 2 页**逐页对齐正确**
（md p3→PDF p3、p8→PDF p8 全部命中），但 PDF 文本层该页是空的，锚串只存在于
MinerU 的 OCR 结果里。**引用页码是对的，参考系是短板。**

因此这类页单列为"无法核验"而不是记为失败 —— 既不藏起真实缺陷，也不让指标被
参考系的缺陷拖成劣化告警。当前 46 条标注里有 1 条属此类。

## 结构化输出评测（`score_structured.py`）

```bash
python -m eval.score_structured --detail
python -m eval.score_structured --save-baseline
python -m eval.score_structured
```

两个语料来源：

1. **真实历史产物** —— `data/stock_data/answers_qwen_turbo.json` 里 `value` 是整坨
   JSON 字符串的记录，即当初剥围栏失败、原文被塞进 `final_answer` 的现场。
   它们用的是**当时的契约**（`relevant_pages: List[int]`），因此必须用
   `LegacyStringSchema` 回放，否则是对着过期契约测，等于没测。
2. **人为畸形** —— 覆盖其余解析阶梯，以及**必须失败**的非法情况。

`false_accept_rate` 是关键指标：解析失败会被丢弃并记日志（可接受），
而**误放会让原文伪装成答案流进提交物**（危险得多）。所以"应该失败"的用例
失败才是正确行为，单独统计。
